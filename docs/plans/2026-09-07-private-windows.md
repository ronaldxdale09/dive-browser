# Private windows

Implement a separate private browser process so normal SQLite, agents, extensions, and website contexts cannot accidentally receive private browsing events. One parent-owned stdin channel creates additional windows in the same private process. Private windows share CEF off-the-record storage (empty cache path); the private chrome keeps that context alive until the last window closes. The application database is in memory. A private temporary root contains only required runtime metadata, not a disk-backed website profile, and is removed on clean exit by the child. A forced kill may leave runtime metadata in the operating system temporary directory; website storage remains off the record. No persistent application logging, crash dumps, AppKit restoration, MCP server, extension loading, agent credentials, automatic update checks, saved bookmarks, or profile import in private mode. Explicit downloads and exports remain on disk. This is local privacy, not anonymity from websites or networks.

The existing one-tab detached-window design is retained. Closing the private main window while detached windows remain hides the host and closes its attached tabs; the last visible private window ends the process. New Tab can reveal the primary window again. Normal windows retain their behavior.

UI: muted ink/violet surfaces, persistent shield Private badge, concise info popover that covers native content safely, dedicated private welcome, and private window titles. File menu, browser menu, palette, and keyboard use Shift+Command/Control+N. New Workspace moves to Control/Command+Alt+Shift+N.

Validation: shortcut/menu parity; private database and command policy; CEF empty cache and context sharing; cookies/localStorage separate from normal and shared between private windows; state survives closing the primary private window; last-close and fresh-session wipe; no SQLite/history/log files in private root; normal profile unchanged; native UI and keyboard verification; pnpm check and exact-binary live checks.
