# DIVE 8/10 Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Meet every outcome in the readiness specification before assigning an 8/10 engineering rating.

**Architecture:** Separate native creation admission from CEF completion with explicit pending ownership. Keep hang detection independent of the UI thread and reuse native automation for causal regression checks and long workload verification.

**Tech Stack:** Rust, Tauri/CEF, Winit, React, TypeScript/Vitest, Python, macOS and Windows.

**Spec:** `docs/audits/2026-09-13-readiness-spec.md`

## Global Constraints

- Use disposable profiles and mock keychains; preserve installed browsers and unrelated worktrees.
- Keep sandbox, privacy protection, GPU settings and discard policy intact.
- Do not skip or weaken the failing media check to obtain a pass.
- Do not upload telemetry or collect page URLs, text, credentials or private browsing content.
- Native Windows execution and at least two continuous hours of final-code workload per platform are required.
- A rating requires current evidence for every spec outcome, not a subset of passing tests.

## Task 1: Correct viewport overflow visibility

**Files:** Modify `apps/desktop/src-tauri/src/inject/actionability.js`; test `apps/desktop/src/test/injectedVisibility.test.ts`.

**Interface:** Preserve `isVisible(el): boolean`, consumed by the injected locator engine. No new public API.

**Evidence:** On the released native binary, YouTube's large Play button has a visible 68 by 48 rectangle centered near (368.5,332.375); every ancestor is visible. BODY has `overflow-x:auto; overflow-y:scroll` and a zero-height rect; the existing ancestor loop returns false. Chromium visibly paints and hit-tests the button. CSS Overflow 3 section 3.3 propagates root/body overflow to the viewport; those boxes do not clip as ordinary ancestors. https://www.w3.org/TR/css-overflow/#overflow-propagation

- [x] Add a failing regression using `withBox(document.body, {width:1000,height:0})`, a visible button at `{x:100,y:200,width:68,height:48}`, BODY overflow auto/scroll and root overflow visible. `expect(visible("css=#b")).toBe(true)` must fail before the fix.
- [x] Add negative cases: ordinary zero-height overflow-hidden wrapper remains invisible; BODY clips when root overflow prevents propagation; containment preventing propagation must not be silently exempted. Reset root/body styles and overridden geometry between tests.
- [x] Run `pnpm --filter @dive/desktop exec vitest run src/test/injectedVisibility.test.ts` and retain failing output.
- [x] Implement the CSS viewport propagation exception using ownerDocument/documentElement/body identity and computed styles, not hostnames. Treat root clipping as viewport behavior, preserving locator scrolling for offscreen controls. Apply ordinary ancestor clips per axis. Cover any additional branch with a behavioral regression.
- [x] Run the focused visibility and injected locator tests, then lint/typecheck. Commit only the scoped change. A native fixture and actual YouTube verification are required in Task 2; passing jsdom is not native proof.

## Task 2: Reliable automated media interaction

**Files:** `scripts/live-check.sh`, new `scripts/media-playback-check.py`, new `scripts/tests/test_media_playback_check.py`; only if evidence requires, `apps/desktop/src-tauri/src/automation.rs` and locator files.

**Interface:** CLI takes explicit MCP data directory, port and tab ID. Returns JSON playback evidence and nonzero on failure; imported pure observation/decision helpers support deterministic tests.

- [ ] Capture intended target bounds, actual trusted pointer targets, scroll changes, video identity and timing before/after the existing click. Preserve raw failing evidence in `target/readiness-8/`.
- [ ] Reproduce any coordinate or player-state defect in a local HTML fixture. Write failing tests for the confirmed causal change before implementation.
- [ ] Select an actually visible startup Play control only when needed; a playing video must not be toggled to Pause. Require at least 1.5 seconds of advancement on the same connected video with `readyState >= 2` and `paused == false`; reset observation on replacement, reject navigation to another video, bound all waiting, and retain final diagnostics on timeout. No DOM `.click()` or unconditional `play()` substitute for trusted input.
- [ ] Run actual released/updated native browser input against local fixtures and YouTube. Integrate the helper into the full harness only after evidence supports it, then repeat with a fresh profile three times.

## Task 3: Asynchronous native creation and lifecycle

**Files:** `vendor/tauri-runtime-cef/src/{webview,runtime,request_context,window}.rs`, `vendor/tauri-runtime-cef/src/browser/client/*`, new focused pending-creation module as needed; desktop engine callers only where their readiness contract requires updates.

**Interface:** Existing Tauri synchronous construction APIs admit a pending view without waiting for CEF. Completion arrives on the native event loop; browser-dependent operations retain order or receive an explicit terminal creation error. Detailed ownership design comes from the read-only native creation report before edits.

- [ ] Write down the transition table for admitted, context-ready, CEF-accepted, attached, canceled and failed creations, and the exit ownership invariant. Review every call site relying on immediate browser existence.
- [ ] Write failing state-machine tests for close during context initialization, close after CEF acceptance, completion after cancellation, duplicate completion, context rejection, pending reparent, bounded queued operations and shutdown with pending children.
- [ ] Replace synchronous creation/deferred pumping with callbacks and posted native completion messages. Keep native parent handles alive through accepted CEF creation and browser-close acknowledgement. Preserve permission initialization, document-start registration, private-context sharing, scheme cleanup, accessibility, bounds and theme.
- [ ] Run vendored runtime tests and strict compilation, then desktop checks. Native tests must exercise initial chrome creation, tab churn, detached windows, close/reopen, and renderer recovery; measure responsiveness over at least 100 creations.

## Task 4: Local crash and hang monitoring

**Files:** New `apps/desktop/src-tauri/src/responsiveness.rs`; `lib.rs`, existing crash reporting and diagnostics export paths if needed.

**Interface:** One independent OS thread sends at most one pending UI acknowledgement; bounded local records contain only timestamp, duration, event kind and app version. Start/stop follows application lifecycle. Private sessions persist no diagnostics.

- [ ] Test normal acknowledgements, sustained stall, one report per stall, recovery, machine suspend gaps, bounded retention, stop with pending acknowledgement, and disabled persistence in private mode using an injected monotonic clock and event sink.
- [ ] Implement a two-second stall threshold and one-second sample interval, independent of Tokio/UI progress. Keep the native callback to an atomic acknowledgement, with disk writes on the observer thread and bounded file rotation.
- [ ] Deliberately stall a disposable native app and prove detection plus recovery; prove ordinary tab churn stays below the threshold and shutdown leaves no monitor worker. Existing panic/renderer crash reports must remain functional.
