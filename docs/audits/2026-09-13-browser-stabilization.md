# Browser stabilization — 13 September 2026

Implementation on `dale/browser-stabilization`, based on the investigation of 134 recent commits through `52fd7c9a56acbac577fe018a34c5197839daffc5`. Changes are uncommitted. The existing five-line generated-binding comment deletion is preserved. The installed `/Applications/Dive.app` has not been replaced.

## Changes

1. **Immediate macOS dialogs.** Native overlays no longer request a page screenshot before opening a modal. Registration runs in a React layout effect. A renderer that never answers screenshot IPC cannot delay Settings, Apps, Library or the palette. Lazy chunks display an accessible, cancellable loading dialog. Nested cover transitions reset state and serialize native restoration. Windows retains the screenshot fallback for modals because its window region clips both painting and mouse input; live menus remain supported.
2. **Snapshot consistency.** Workspace/profile refreshes coordinate request and intent revisions. Core/window events crossing a snapshot are replayed over its result. A bounded 1,024-delta history avoids title-event starvation; overflow takes a fresh snapshot. Older operations cannot close a newly opened editor. Boot waits for hydration.
3. **Bounded intercepted requests.** Failed protected requests retry as blocked, never as plain continue. Other failed requests get one terminal fallback. Unresolved requests share a per-tab recovery operation with a two-second stop-loading deadline, preserving protection. Invalid interception IDs are treated as already cancelled. Main-document epochs prevent older request recovery from stopping a newer navigation; iframe loads do not invalidate the main document. Recovery failures are visible in the UI.
4. **Native responsiveness.** Native message draining yields after 64 messages or four milliseconds. Expired queued main-thread commands do not execute later. Window geometry persistence runs in one coalescing blocking worker rather than SQLite writes in native move/resize callbacks. Overlay animation updates only the native mask instead of re-showing every page and restoring accessibility repeatedly.
5. **Protocol memory and delivery.** Raw ingress is bounded to 4,096 messages and 64 MiB per session, with reservations retained during parsing. Overload explicitly stops the affected session and shows recovery UI rather than dropping critical requests silently. User Retry/navigation reconstructs the failed native page while retaining the tab and detached/split placement. CEF command rejection is forwarded asynchronously to the original CDP call instead of being discarded and turning into a 30-second timeout.
6. **Telemetry.** Console/network history remains immediate and bounded in the host. Frontend IPC batches up to 64 items or 16 ms. Console navigation reset markers share the ordered batch stream; closed sessions discard pending UI batches. Existing frontend folding, caps and preserve-log behavior remain in place.
7. **Reproducible checks.** `pnpm check` and local release tooling share a link-tested SDK preflight. `pnpm check` now includes the vendored runtime's tests. Winit is pinned to the beta version actually used by the app; the newer beta selected by standalone dependency resolution did not compile against this runtime.

## Verification

- `pnpm check`: passed — 1,275 frontend tests, 660 workspace Rust tests, 50 vendored-runtime tests, and 31 Python probe tests. One frontend test is skipped; six Rust tests remain intentionally ignored. TypeScript, ESLint, formatting, Vite production build and Clippy also passed.
- Native macOS debug bundle built successfully. A separately named, ad hoc signed copy used only disposable data and the mock keychain for computer-use verification.
- Sustained local workload: 1,000 console messages/second and 40 request attempts/second configured; over 170,000 console messages and 8,000 requests observed. Settings, panel switching, Apps-to-Library transitions, palette input and page popup creation worked while the canvas continued animating.
- Two instrumented New Tab command-to-React-mount samples: **3.5 ms and 3.3 ms**. These are not input-to-paint latency or a broad percentile benchmark.
- A deliberately scheduled ten-second renderer busy loop did not prevent Settings from appearing in the native accessibility tree.
- Forced a single protocol message larger than the 64 MiB budget: the browser displayed the overload error; clicking Retry recreated the page with the same tab ID and restored rendering.
- Ten-tab memory probe: nine background tabs discarded; total process RSS fell from 1,246,608 KiB loaded to 985,952 KiB after sweeping, reclaiming 260,656 KiB (about 255 MiB), or 60.99% of growth above the 819,200 KiB baseline. This was a 41-second local same-site workload on the debug build, not a leak or long-term soak assessment. See `memory.log` and `target/memory-probe-1789230661810699000/`.
- Isolated native YouTube playback passed manually. The public test clip rendered; native mute/play controls worked, and on replay the same video element advanced from 9.206 to 11.709 seconds over 2.5 seconds, with `readyState=4`, `paused=false`, and `ended=false`. See `youtube-playback-replay.json`. This does not qualify every media codec, DRM service or GPU configuration.

## Limits and follow-up

This is a tested stabilization change set, not a guarantee that every freeze has been eliminated. Individual native view creation still uses CEF's synchronous creation/deferred-initialization path; time-slicing cannot interrupt one long native operation. A larger asynchronous lifecycle change and production hang telemetry remain follow-up work. No GPU backend flags, sandbox settings, automatic discard thresholds or protection settings were weakened.

Native Windows execution and a multi-hour soak have not been performed. Windows modal input shielding is required before enabling the immediate live-modal path there. Under overload, explicit Retry recreates a renderer: page-local unsaved state and its in-memory back stack cannot be recovered. Normal healthy-tab reload/navigation keeps its existing view.

The first live harness run failed at YouTube input while another native UI test was active; an isolated rerun reached the player but it removed the video before the playback assertion. These automated failures are retained as evidence, not counted as passes; the separate native playback check above subsequently succeeded. Local qualification passed with only external YouTube skipped: navigation, screenshot, sandboxed renderers, popup, PDF, offline recovery, in-flight tool protection, discard/wake, crash isolation and four lifecycle runs. Camera/microphone consent checks were skipped because OS permission was not pre-granted. The four debug-bundle exits completed normally in 8.13, 6.96, 7.77 and 7.07 seconds; these are not directly comparable with the earlier optimized release baseline. CDP p50/p95/max were 0.163/0.356/0.865 ms across 100 calls. See `live-local.log` and `target/lifecycle-probes-1789230600675711000/summary.json`.
