# Generation-bound crash recovery and native qualification

A delayed native termination callback originally discarded the view generation from its label, admitted a recovery against the tab ID, then fetched that tab's current CDP session in its deferred worker. A recreated view for the same tab could therefore be reloaded by its predecessor's crash. Old reports could also spend the replacement's retry budget.

The crash registry now binds each tab to its exact current native view label. Binding changes, admission, and retirement follow a consistent view-lock-before-history order; native callbacks never acquire the tab host lock. Both native and CDP reports retain their source label. Stale sources are rejected before admission, native workers require an exact current host label before selecting a session, and deferred reloads cannot clear a replacement's duplicate-report state. Synchronous admission still folds native/CDP signals before worker scheduling. New generations start a fresh budget; rebinding the same label preserves it.

Source review caught a further check-before-publication race. Crash notices now validate and emit together in one main-thread dispatch, serialized with native view replacement, without holding registry or host locks across event publication. Controlled regressions cover stale reports, replacement budgets, closed-history retention, old reloads affecting deduplication, deferred admission and queued UI publication. Fifteen focused crash/probe tests pass; strict Clippy passes. Workspace library tests443 passed before final style-only extraction. Python harness19 pass. Final pnpm check is recorded below when complete.

The new optional DIVE_CRASH_PROBE runs only in the explicit mock-keychain/disposable-profile native harness and rejects process-model overrides. It creates separate native RequestContexts, verifies non-sharing and different renderer isolates, installs one-time document sentinels, then issues Page.crash exactly once. Success requires an actual crash event, exactly one attempt-1 recovery, a fresh target document and loader, unchanged native tab ID/view label/Browser ID, unchanged sibling/chrome sentinels/timeOrigin/loaders/isolates and no document replacement events, and working chrome IPC. It does not prove crash-budget exhaustion or PID-level isolation, nor inject a delayed obsolete native callback; those generation checks have controlled regression coverage.

The old live-check.sh crash step killed every direct renderer, then mistook eventual recovery for an unchanged sibling. It now finishes its own fixture and runs the new isolated native qualification on the same exact binary. Cleanup is idempotent after explicit fixture teardown. A real run exposed a stale permission-test deadline: native PermissionBridge allows30seconds, but the test waited15seconds. The harness now waits35seconds for actual timeout denial; production permission policy is unchanged.
