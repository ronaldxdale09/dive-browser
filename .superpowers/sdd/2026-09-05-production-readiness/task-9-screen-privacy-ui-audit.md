# DiveScreen and DivePrivacy UI audit

Source inspection only, 2026-09-05, isolated production-readiness worktree. No native apps launched, builds/tests run, or implementation files changed. Findings below describe current source behavior; actual pointer routing, visual layout, codecs, OS dialogs and persistence require the native checks below. Existing permission diagnostics were preserved.

## Flow map

- Recording: FeatureBar `Record` / Cmd+Shift+R → `record/RecordDialog.tsx` → `store/recording.ts` → native screencast. Setup offers tab, Page/Window, MP4/GIF, 15/30 fps, 720p/1080p, microphone and countdown. Missing ffmpeg disables video/window/mic. FeatureBar HUD provides countdown cancel, recording pause/resume/stop/discard and save status. Done dialog provides preview/system-player fallback, Open, Finder, Copy path, Delete/Keep, Record another and MP4 Edit in DiveScreen.
- Editor entry: `components/MainMenu.tsx:222–228,255` loads the newest *editable* recording on menu mount; `components/Library.tsx:323` lists recordings with edit actions; Done dialog offers MP4 editing. `internal/InternalPage.tsx:21,42` routes `dive://screen?src=...` into the lazy editor. `Content.tsx:41,67` mounts only the active internal tab.
- Editor: `screen/DiveScreen.tsx` contains Save, Finder, Return to Recorder, Undo/Redo and Export. `Timeline.tsx` provides play/seek, zoom, trim, text, speed, blur, region dragging and aspect ratio. `SettingsPanel.tsx` provides background presets/colour/image, padding/roundness/shadow, crop, cursor and selected-region controls. Preview uses `Stage.tsx`; project JSON is a sidecar (`screen.rs:214–234`). Export renders VP9/WebM frames in chrome, uploads staging chunks and invokes ffmpeg for MP4/GIF.
- Privacy: `components/ProtectionMenu.tsx` offers typed per-tab ad/tracker counts, YouTube preference, exact-host pause/resume, global enable when off, rules version and All privacy settings. It covers native content and traps focus. `SettingsDialog.tsx:284–414` adds global protection, YouTube, removable host exceptions, DNT/GPC, JavaScript, custom URL globs, history retention, browsing-data deletion and site permissions. Preference updates are serialized and failures reported/rolled back by `store/prefs.ts:106–145`. Native `commands.rs:266–288` persists then refreshes open-page policy.

## Source-confirmed gaps, ordered by impact

1. **MP4 export selects a nonexistent audio input.** `screen/export.ts:113–120` creates a video-only WebM and line177 requests audio for every MP4. `screen.rs:382–388` opens that WebM as input0 and the source recording as input1, but `audio_filter` at line334 selects `[0:a]`. Normal nonempty MP4 export therefore asks ffmpeg for audio absent from input0. Silent recordings also need actual source-audio detection; microphone-off recording is supported (`screencast.rs:1020–1057`). Fix needs the correct input index plus audio-presence gating, verified with both silent and audio fixtures.
2. **Switching away can discard edits before autosave.** `screen/store.ts:139–143` clears the 600ms timer and drops the dirty project without flushing. `DiveScreen.tsx:28–35` invokes close on unmount; `Content.tsx:67` unmounts on tab change. An edit followed immediately by switching tabs can be lost. No close/save confirmation or pending-write flush exists.
3. **Async project identity is unguarded.** `screen/store.ts:109–135` applies results of multiple awaited calls without checking that `source` still owns the load. Slow recording A can overwrite B after switching; `save:258–267` similarly clears dirty after an old write even if a newer edit/source exists. The singleton store and active-tab mounting make this reachable without two simultaneous editors.
4. **Export Cancel is incomplete; failures can leak resources/staging.** `screen/export.ts:31–55` seek has neither abort handling nor deadline. Abort checks cover only frame-loop entry and upload chunks; encoder drain/flush and native finishing ignore cancellation. `screen.rs:310–324,410–412` waits for an uncancellable ffmpeg process. Staging is removed only through finish; abort during upload leaves `.export/render-*.webm`. Several exceptions after encoder/video creation bypass cleanup because no enclosing `finally` covers the full pipeline. Export dialog still presents Cancel while finishing (`ExportDialog.tsx:121–132`).
5. **Export dialog lacks keyboard containment/dismissal.** `screen/ExportDialog.tsx:69–70` sets `aria-modal` but has no focus trap or Escape handler. Unlike Record/Done dialogs, keyboard focus can move to controls behind it; backdrop/Close are the only dismissal handlers. Success Open/Finder calls also omit rejection feedback (`:142–147`); top-bar Finder explicitly swallows errors (`DiveScreen.tsx:97`).
6. **Recording discard can falsely report success.** `store/recording.ts:209–214` suppresses native cancellation failure then clears recordingTab and returns idle. A failed native cancellation can leave capture active while UI reports stopped. This needs a controlled failure regression, not an OS-device test.
7. **Privacy inconsistency, lower severity:** the card's YouTube switch is disabled only off supported hosts (`ProtectionMenu.tsx:139`), while Settings disables it when global protection is off (`SettingsDialog.tsx:312`). The card accurately says Inactive, but still permits changing an ineffective preference. No inert main protection controls were found. Native enforcement/counter accuracy is unverified by this inspection. Settings rules version has only `…` fallback, unlike the card's explicit Rules unavailable state.

## Native computer-use acceptance sequence

Use a disposable profile and exact fingerprint. Prefer a local animated page and microphone Off; optional audio/window capture needs a separately authorized fixture. Record screenshots and actual output-file/playback evidence, not only store values.

1. **Entry/cancel:** with no recordings, MainMenu Edit Latest is disabled. Open Record via toolbar and shortcut; select a real page, change every format/size/fps option, cancel by button/Escape, and cancel during countdown. Open from DiveScreen Return to Recorder and verify an internal editor tab cannot silently become an invalid capture target.
2. **Record/save/recovery:** record 5–10 seconds with visible pointer movement/clicks; pause, wait, resume, stop. Check elapsed duration excludes pause, preview plays and saved metadata matches file. Exercise Copy path, Finder, system Open, Delete→Keep, Done, Library reopen and Edit Latest. Repeat GIF; simulate decoder failure/missing companion only in disposable fixtures and check recovery messaging.
3. **Edit:** scrub/play, add and move/resize one zoom, trim, speed, text and blur region. Change background, padding, crop and cursor settings; compare preview; Undo/Redo and keyboard shortcuts. Save, switch away/back, restart and reopen. Specifically change then switch within600ms, and rapidly alternate two recordings to expose findings2/3.
4. **Export:** after fixing finding1, export silent MP4 then an audio fixture and GIF; verify real playback, duration/trim/speed/annotation/audio sync and dimensions. Exercise Open/Finder/Done. Cancel once during rendering, upload and finishing; assert no output claimed saved, no orphan encoder/staging and editor remains usable. Test unavailable encoder, malformed source and output failure with visible retry. Tab/Escape must remain within/close Export appropriately.
5. **Privacy defaults/enforcement:** open local controlled ad/tracker fixtures; inspect card status and distinct counts, reload to reset, switch tabs to prove isolation. Pause exact host, reload and verify requests/content resume; a sibling host stays protected. Resume from card and Settings; restart and verify persistence. Do not equate generic network failures with blocked actions.
6. **Privacy controls/recovery:** toggle global protection, YouTube preference on/off supported host, DNT/GPC and JavaScript; verify actual requests/script behavior after reload. Add/remove a custom local URL rule and test independently of curated protection. Exercise keyboard focus, Escape/outside close, dark/light and narrow window. Simulate preference/rules/events failures in a disposable test boundary: show truthful unavailable/error state, rollback and usable retry. YouTube external playback remains a separate explicit runtime gate.
7. **Data/permission scope:** in disposable fixtures only, preview and cancel browsing-data deletion; then delete selected categories and verify other categories remain. Test remembered permission reset within its displayed profile/container scope using existing device-free native permission qualification. Chooser/protocol migration and unsupported temporary native-prompt grants remain open in Task4; this UI audit does not qualify them.
