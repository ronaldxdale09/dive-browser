# Restore open discarded tabs and use available tab-strip width

Computer use on exact a5905b99 reproduced closing an active Alpha tab while the only remaining Beta tab was discarded: the browser showed Welcome and retained Beta in the strip with count 1. Store::last_active_tab incorrectly excluded discarded rows. Discarding retires a renderer while preserving an open tab; it does not close the tab.

The query now selects by workspace and recency regardless of renderer state. Existing activate_tab recreates the native view and loads the persisted URL. The remembered-tab startup filter similarly retains workspace isolation while accepting discarded tabs. Deterministic regressions prove that the remaining discarded tab is selected after an actual row removal, a newer discarded tab outranks older active/sleeping tabs, foreign workspaces are excluded, saved URL/identity survive, and removing the final tab yields no replacement. Both new regressions failed before the fix (session tool output); all 31 core tests pass afterward.

The same native run showed short titles truncating with large unused space in the tab bar. Each unpinned tab had only flex-basis, so the auto-sized parent used its content width. A definite w-56 now supplies its intended intrinsic 224-pixel width while existing shrink, minimum and maximum rules still compress crowded strips. Pinned styles are unchanged. Seventeen existing TabStrip tests and TypeScript checking pass; these do not prove pixel layout. Source review and strict workspace Clippy pass.
