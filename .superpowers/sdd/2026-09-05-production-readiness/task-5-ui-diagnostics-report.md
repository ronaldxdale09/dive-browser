The opt-in DIVE_UI_PROBE=1 diagnostic requires an explicit test profile and mock keychain, and rejects competing lifecycle/stress/smoke/CDP benchmark modes. A dedicated worker records native window visibility/focus/minimized state, chrome bounds and native browser validity, document readiness/geometry/input event-type counts, and a separate read-only snapshot IPC acknowledgement. It records no typed values, page URLs or snapshot contents. A separate OS-thread watchdog stops new operations after a 15-second stall, including when a delayed operation subsequently returns. It never starts replacement workers. Screenshots occur only when the operator creates capture.request in the disposable profile's ui-probe directory; periodic screenshot polling could alter compositor behavior.
