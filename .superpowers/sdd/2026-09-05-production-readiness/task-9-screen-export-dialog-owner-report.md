# DiveScreen export dialog ownership

`ExportDialog.run` formerly cleared the current editor's global exporting flag unconditionally in finally. A's native finish can remain pending after its dialog unmounts; B can open and export meanwhile. When A resolves, its stale finally cleared B's flag, allowing B's Stage subscription/RAF to resume playback/seek operations on the decoder that B's exporter borrowed. This is a source-confirmed race, not an established explanation of native16.

Scope: `apps/desktop/src/screen/ExportDialog.tsx`, new `ExportDialog.lifecycle.test.tsx`, and existing dialog test fixture initialization. Run admission synchronously claims one unique object-identity token and captures editor generation before calling the exporter. A second admission or remount within the same generation cannot overlap. A newer editor generation can supersede a pending old native finish; only its matching owner/generation may release global exporting. Local progress, errors and results require a mounted matching owner. A remounted dialog that attempts an export while its original generation is still finishing receives a retryable explanation. The old native operation is not cancelled or misrepresented as cancelled.

Three controlled regressions failed RED and passed GREEN: A native finish after close/openB/startB cannot release B or display A's result; duplicate synchronous clicks before progress/React rerender invoke the exporter once; a same-generation remount cannot overlap the old pending finish and can retry after it settles. Final31 focused tests (7 dialog,4 media helper,16 exporter,4 Stage) pass. Scoped ESLint and full frontend typecheck pass. Logs `/tmp/dive-export-dialog-owner-{red,green,final}.log`; copies `target/screen-export-dialog-owner-regression/{red,green}.log`. Existing keyboard dialog tests now initialize distinct editor generations, reflecting separate editor sessions rather than allowing an intentionally forever-pending mock to own later tests.

No backend/IPC/native cancellation changes, builds or app launches by this agent. Native job cancellation and staged-file cleanup remain OPEN. Source review requested; root owns the combined build/live proof.
