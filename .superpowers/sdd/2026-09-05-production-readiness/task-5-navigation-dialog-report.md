# Foreground navigation dialogs and native content coverage

Computer use in an 800x600 native window exposed New Tab beneath Settings: Cmd+T could leave Settings visible, and Escape revealed an already-open Palette underneath. Source confirmed both independent open flags stayed true; Settings renders later than Palette at the same z-index. This was not attributed to the unresolved whole-window black capture.

Palette, Settings, Library and Shortcuts now replace one another through the shared state transition used by toggle, openSettings and openLibrary. Opening one clears the other navigation dialogs and launcher menu atomically. Closing one does not resurface another. Sidecar, developer dock, find, extensions, subtitles, default-browser UI, workspace/profile editing, annotation and recording state are preserved. This is deliberately a bounded navigation-dialog policy, not a universal dismissal rule for editing workflows.

Review found that unmounting the old dialog could briefly release the native page cover before its replacement mounted, especially while loading a lazy chunk. App now holds a stable group cover outside Suspense; individual dialog covers remain valid for standalone rendering. Component regressions observe the actual IPC calls: Settings to Palette and a suspended lazy replacement use one capture and one hide, no intermediate uncover, then one uncover on final Escape. The tests failed before the stable group cover was added.

An independent frontend race was also reproduced: a delayed successful or rejected uncover response for dialog A could erase dialog B's newer frozen preview. Final cleanup now checks its generation and that no cover remains before publishing an empty preview. Deferred-response tests reproduce both outcomes and verify that the current final close still clears its preview, including failures. Native command order and timing are unchanged. This is a controlled frontend regression; native response reordering was not forced or demonstrated.

Source review closed the state, cover and finalizer findings. Focused 115-test suite passes (target/overlay-finalizer-green.log); red evidence is retained in target/navigation-cover-red.log and target/overlay-finalizer-red.log. Canonical pnpm check passes 700 frontend tests with one opt-in benchmark skipped, 447 Rust tests and 19 Python harness tests, plus formatting, TypeScript, lint, Vite build and strict Clippy (/tmp/dive-dialog-final-check.log).
