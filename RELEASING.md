# Releasing Dive

Dive uses a streamlined, deterministic release pipeline designed to make shipping desktop updates effortless.

---

## 🚀 One-Command Release Cut

### Option A: Via GitHub Actions (Zero Local Setup)
1. Go to **GitHub Actions** $\rightarrow$ [**`release`**](.github/workflows/release.yml) $\rightarrow$ **Run workflow**.
2. Select your release kind:
   - `rc` (Release Candidate, e.g. `0.1.1-rc.0`)
   - `patch` (Bug fixes & polish, e.g. `0.1.1`)
   - `minor` (New features, e.g. `0.2.0`)
   - `major` (Major milestones, e.g. `1.0.0`)
3. Click **Run workflow**. 

The workflow automatically:
- Computes the monotonic semver version.
- Bumps `Cargo.toml`, `apps/desktop/package.json`, and `apps/desktop/src-tauri/tauri.conf.json`.
- Commits and pushes the release tag `vX.Y.Z`.
- Runs preflight tests, compiles the macOS `.dmg`, and packages updater artifacts (`.tar.gz`, `.tar.gz.sig`, `latest.json`).
- Publishes the release directly to GitHub Releases.

---

### Option B: From Your Local Terminal

You can also cut and push releases directly with a single command:

```bash
# 1. Preview what version will be cut
pnpm release:check rc       # e.g. 0.1.1-rc.0
pnpm release:check patch    # e.g. 0.1.1
pnpm release:check minor    # e.g. 0.2.0

# 2. Dry run to see what files will change without modifying anything
pnpm release rc --dry-run

# 3. Cut, commit, tag, and push to GitHub in one command
pnpm release rc --push      # or: pnpm release patch --push
```

Once pushed, GitHub Actions automatically builds the release bundle and attaches download links!

## 🔐 Codesigning & Updater Keys (Optional / Production)

For official public production releases with macOS Gatekeeper notarization and cryptographic updater verification, configure the following secrets in **GitHub Repo $\rightarrow$ Settings $\rightarrow$ Secrets and variables $\rightarrow$ Actions**:

| Secret | Description |
|---|---|
| `APPLE_CERTIFICATE` | Base64-encoded Developer ID Application `.p12` certificate |
| `APPLE_CERTIFICATE_PASSWORD` | Password for the `.p12` file |
| `APPLE_SIGNING_IDENTITY` | Identity string (e.g. `Developer ID Application: Your Name (TEAM_ID)`) |
| `APPLE_ID` & `APPLE_PASSWORD` | App-specific password for Apple notary service |
| `APPLE_TEAM_ID` | 10-character Apple Developer Team ID |
| `TAURI_SIGNING_PRIVATE_KEY` | Private key generated by `tauri signer generate` |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Password for the private key (or empty if none) |
| `TAURI_SIGNING_PUBLIC_KEY` | Public key paired with `TAURI_SIGNING_PRIVATE_KEY` |

> [!NOTE]
> If Apple signing certificates are not configured, the release workflow gracefully falls back to building unsigned development/testing DMGs so releases are never blocked during testing!

## 🔄 How In-App Push Updates Work

1. **Background Polling**: 10 seconds after launch, Dive queries `https://github.com/ronaldxdale09/dive-browser/releases/latest/download/latest.json`.
2. **Signature Verification**: The updater checks the cryptographic signature using the embedded public key.
3. **User Alert**: An **Update available** pill smoothly appears in the FeatureBar.
4. **Instant Update**: Clicking **Install and restart** swaps the application binary and relaunches Dive while preserving open tabs and workspaces.
